# 战斗框架 v0.13：武器自定义系统（草案）

> 状态：草案，供评审。承接 v0.12。2026-11-17 第五轮修订：装不上改为红色提示、允许保存；容积随模块尺寸设计而定，不预设固定格数；形状可旋转、可镜像；伤害类模块新增朝向判定（朝敌、朝己、朝上下）。数值仍待模拟。

## 1. 已拍板

| 项 | 决定 |
|---|---|
| 自定义方式 | **A + B 组合**：B 管容积与形状（拼积木），A 管模块效果 |
| 插槽 | **武器有容积**，格子有形状，不是一字排开 |
| 容积大小 | **随模块的设计尺寸而定**，不预设固定格数（见第 4.2 节） |
| 形状操作 | **可旋转、可镜像** |
| 模块属性 | **重量**、**操作**、**攻击供能需求**、**防御供能需求**。**没有尺寸概念** |
| 属性叠加 | 模块的重量与操作**叠加到武器基础属性上**，玩家设计完后得出**最终属性** |
| 最终判定 | 单手、双手，或**装不上**。装不上只做**红色提示**，**允许保存** |
| 武器基础卡 | 每把武器基础 **4 张卡** |
| 模块用法 | 可**替换**一张基础卡，也可**直接加入卡组** |
| 终极卡 | 改装完成后生成 **1 张**，**额外加入卡组**，不占基础卡位 |
| 终极卡名字 | 玩家自定义，提供**随机名字按钮** |
| 同名模块 | 每件装备**同名只能插 1 个** |
| 同类模块 | **允许反复装** |
| 终极卡附带效果 | **无上限**，由已插模块决定；每个模块的展示效果在设计时预先写好 |
| 终极卡类型 | 由武器基调 + 模块主类型决定，效果同类 |
| 朝向判定 | **伤害类模块**有朝向，决定目标（见第 5 节）；**非伤害类模块不受影响** |
| 供能分配 | **10% 一格** |
| 武器基础功能需求 | 与武器本身相关，每把武器各自设定 |
| 武器大类 | **近战**、**远程** |
| 武器品类 | 每个大类下有多个品类（如近战：刀、剑、爪；远程：待定） |
| 品质等级 | 每个品类分 **3 级：蓝、紫、橙** |
| 同品类不同等级 | 基础供能、基础属性有差异，但**差异不大**；外形差异要明显 |
| 模块分类 | 只分**近战模块**、**远程模块**两大类 |
| 模块通用性 | 大类内**绝大多数模块通用**；极少数只能装在特定武器类型上 |
| 模块尺寸 | **2～4 格**，3 格常用，5～6 格仅特殊少量 |

## 1A. 模块分类与通用性

- **大类**：近战模块、远程模块。近战武器只能装近战模块，远程武器只能装远程模块。
- **通用**：同一大类内，绝大多数模块可以装在该大类的任意武器上。
- **限定**：极少数模块只允许特定武器类型安装（例如仅刀类、仅枪械）。限定规则在模块表里逐条标注。
- 这一设计让模块池保持简单，玩家不必为每把武器记忆大量特例。

### 2 格模块需要慎重设计

2 格模块形状最小，**可以填进任何空隙**，是拼积木时最灵活的工具。这带来两个风险：

1. **万能补洞件**：如果 2 格模块效果足够强，玩家会用它把所有空格补满，装配变成"只拼 2 格"，其他形状失去意义。
2. **空隙填充的数值膨胀**：2 格模块在每把武器上都能装，同类叠加后很快超模。

**设计建议**
- 2 格模块的效果**弱于 3 格**，但有一个**形状或条件上的额外用途**，例如只在某些朝向下生效，或与相邻模块联动，避免只靠数值。
- 2 格模块的同名限制（每件 1 个）要保留，不然同一个 2 格件可以反复补洞。
- 2 格模块的重量和操作要较轻，否则补洞会导致属性超限，玩家需要取舍。

## 2. 两步判定：先形状，后属性

**形状决定能不能插，属性决定能不能拿。**

### 第一步：形状（能不能放进去）

- 武器的容积是一张有形状的格子图。
- 模块也是有形状的积木，可以旋转、镜像后拼入。
- 形状不能重叠、不能出界。**形状放得下，才能插入。**

### 第二步：属性（最终能不能拿）

- 最终重量 W' = 武器基础重量 + 所有模块重量之和。
- 最终操作 O' = 武器基础操作 + 所有模块操作之和。
- 用手部的承载 C 和操作 P 判定（见 v0.5）：
  - **单手**：某只手同时满足 C ≥ W' 且 P ≥ O'
  - **双手**：两只手合计满足即可，占满两手
  - **装不上**：双手合计也不满足

**"装不上"只是红色提示**：界面实时显示当前属性超出多少，但不阻止保存。玩家可以先存草稿，再回头调整。

## 3. 供能判定

每个模块和武器本身，都有**攻击供能需求**和**防御供能需求**。玩家在回合中分配攻击供能和防御供能，合计 100%，**按 10% 一格分配**。

**定义**
- A = 武器基础攻击需求 + 所有已插模块的攻击需求
- D = 武器基础防御需求 + 所有已插模块的防御需求
- T = A + D（恒大于 0）

**判定规则**
1. 主功能 = 需求较多的一侧。
2. 门槛 = 主功能需求 ÷ T，向上取整到 10% 的倍数。
3. **只需满足主功能**：主功能侧的供能 ≥ 门槛，即可打出终极卡。
4. **只有 A = D 时才需要均衡**：两侧都要 50%。

**例**：A = 4、D = 3，T = 7，门槛 4/7 ≈ 57.1%，向上取整为 60%。

## 4. 武器分类、等级与容积

### 4.1 大类与品类（候选）

| 大类 | 品类（候选） | 说明 |
|---|---|---|
| **近战** | 刀、剑、爪 | 近战手部加成适用（v0.8） |
| **远程** | 待定（如枪械、弓、能量投射） | 远程无手部加成（v0.8） |

### 4.2 容积：随模块设计而定

- 容积不是固定的 8、9、10 格。它**由该品类模块的设计尺寸决定**，也就是先设计模块形状，再反推容积。
- 蓝、紫、橙三级的容积差异依然压小，但具体格数等模块表定下来再写。

**容积推算（估算，待模拟验证）**

假设：模块按格数分三档，小 2～3 格、中 4 格、大 5～6 格；玩家自由拼装，有旋转和镜像，实际填充率按 70%～80% 估计（有空格浪费）。

容积 ≈ 模块总格数 ÷ 填充率

| 目标模块数 | 平均每个模块格数 | 所需容积（填充率 75%） |
|---|---|---|
| 3 个 | 3 格 | 约 12 格 |
| 3 个 | 4 格 | 约 16 格 |
| 4 个 | 3 格 | 约 16 格 |
| 4 个 | 4 格 | 约 21 格 |
| 5 个 | 3 格 | 约 20 格 |
| 6 个 | 3 格 | 约 24 格 |
| 6 个 | 4 格 | 约 32 格 |

**结论（推断）**
- 若要稳定插入 3～6 个模块，容积大致需要 **16～24 格**，模块平均 3～4 格。
- 原来说的 10 格只够装 2～3 个 3 格模块，**太小**，不满足 3～6 个的目标。
- 如果模块普遍 4 格以上，容积要到 24～32 格，拼装会变成大型拼图，界面和扫描压力都会上升。
- 蓝、紫、橙的容积可以按同一模块表的不同子集来定，例如蓝 16、紫 20、橙 24 格，但需要确认三级之间的差异是否仍然"不要太大"。

### 4.3 品质等级：蓝、紫、橙

| 项 | 差异范围（候选） |
|---|---|
| 容积 | 随模块设计，逐级小幅增大 |
| 基础供能需求 | 逐级小幅变化 |
| 基础属性（重量、操作） | 逐级小幅变化 |
| 外形 | **差异明显** |

## 5. 朝向判定（伤害类模块）

### 5.1 规则

以枪管类模块为例：

- **朝敌**（模块朝向敌人方向）：卡片为"对敌人造成 X 伤害"，终极卡上该模块的效果同样是"对敌人造成 X 伤害"。
- **朝己**（模块朝向玩家自己）：卡片变为"对自己造成 X 伤害"，终极卡上该模块效果也变为"对自己造成 X 伤害"。
- **朝上或朝下**：卡片变为"造成 0 点伤害"，终极卡上该模块伤害效果也为 0。

### 5.2 只影响伤害类

- **非伤害类模块不受朝向影响**，无论朝哪个方向，效果不变。
- 朝向只决定伤害的目标和数值，不决定模块能不能插。

### 5.3 对设计的影响

- 朝向是**形状操作的一部分**：玩家旋转、镜像模块，就是在改变它的朝向。所以形状操作与伤害目标直接相关，这是 A+B 组合的一个具体体现。
- 因为要在卡面和终极卡上实时显示朝向，界面需要一个清楚的朝向标记（例如枪口箭头）。
- 朝上朝下归零，是一个明显的"陷阱"设计：玩家容易误装，所以需要红色提示。

### 5.4 基准（已确认）

- **武器永远正面对敌**，武器本身不随玩家改装而转向。
- **模块的朝向**是它在武器上的方向（经过旋转、镜像后），与武器正面比较，决定朝敌、朝己或朝上下。
- 非伤害类模块不做朝向判定。

## 6. 武器卡组张数

- 基础卡：4 张（模块替换基础卡时数量不变）
- 直接加入的模块：d 张
- 终极卡：1 张

**单把武器卡数 = 5 + d**

d 的上限由**容积能放下多少模块**和**属性能否拿得动**共同决定。

---

## 7. 终极卡的效果生成

- 终极卡的主类型由**武器基调**和**模块主类型**决定。
- 每个模块在设计时预先写好它在终极卡上的展示效果。伤害类模块的效果要按朝向写出三种版本（朝敌、朝己、朝上下归零）。
- 改装完成后，系统把已插模块的效果拼成终极卡的描述。
- 附带效果数量无上限，由插入模块决定。
- 因为效果预先写好，组合空间有限，可以用扫描脚本找出超模组合。

---

## 8. 风险

1. **组合爆炸**：形状拼法（含旋转、镜像）× 朝向 × 模块组合 × 供能分配 × 品类 × 等级。必须用扫描脚本。
2. **朝己伤害的误装**：玩家可能无意中把伤害模块装成朝己，造成自伤。需要红色提示，并且卡面和终极卡都要明确写出"对自己"。
3. **朝上下归零的误装**：玩家可能装完才发现伤害是 0。需要在改装界面实时预览，而不是只在战斗中体现。
4. **拼积木的体验**：拼不进去时，界面要清楚告诉玩家是哪块形状挡住了。
5. **装不上的反馈**：属性超限时，实时显示"差多少"。
6. **同类无限叠加**：同类模块可以反复装，靠扫描和数值控制。
7. **10% 跳变**：门槛向上取整，玩家可能差 1% 被卡住，界面要显示"需要 X%"。
8. **终极卡名字**：长度上限、敏感词过滤、随机词库。
9. **2 格万能补洞件**：2 格模块能填任何空隙，效果过强会让其他形状失去意义（见第 1A 节）。
10. **限定模块的误装**：玩家可能找不到能装的限定模块，界面要标明"仅限某类武器"。
